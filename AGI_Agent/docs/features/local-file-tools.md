# 功能：本地只读文件工具

- 状态：已完成（2026-10-12）
- 涉及文件：`src/agi_agent/tools/builtin/files.py`、`tests/unit/test_files_tools.py`
- 相关决策：[0007 工具签名与风险](../decisions/0007-tool-registry-signature-and-risk.md)

## 要解决什么问题

让 Agent 能读取项目里的文件。这是最简单的真实工具，也是**第一个会碰到安全边界的工具**——
它第一次给了 Agent「读取真实世界」的能力，而这个能力必须有边界。

## 最终怎么做

两个工具：`local.list_dir`、`local.read_file`，风险等级均为 `READ`（因此不触发审批）。

**三道边界**，任何一道命中即拒绝：

1. **目录沙箱**：仅 `config.ALLOWED_ROOTS` 内可访问，默认是项目根。
   可用环境变量 `AGI_ALLOWED_ROOTS` 覆盖（多路径用系统路径分隔符）。
2. **凭据黑名单**：拒绝 `.env`、`.env.*`、`*.key`、`*.pem`、`id_rsa` 等**文件名**，
   以及 `.git`、`.ssh`、`.venv`、`.idea`、`.secrets`、`node_modules`、`__pycache__`
   等**目录段**。
3. **容量上限**：单文件截断于 20000 字符，目录列表截断于 200 项。

路径一律**先 `resolve()` 再校验**，因此 `..` 和指向外部的符号链接都会被拦住。

## 为什么这么做 / 被否决的方案

**三道边界各自的完整理由写在 `files.py` 的模块 docstring 里——改动沙箱规则前必须先读它。**
这里只留不在代码里的部分：

- **白名单沙箱 + 凭据黑名单必须双重**：只做沙箱不够，因为凭据往往就在沙箱**内部**
  （这个项目的根目录下就同时放着 `.env` 和 Steam 的登录态）。
- **被否决：允许写文件**。写操作会改动真实文件且难以回滚，在没有审批链路之前不做。
  现在审批链路已经有了（见 [supervisor-graph](supervisor-graph.md)），
  将来加写工具时应设计成 `WRITE` 风险并自动接入审批。

## 已知局限与坑

- 截断是**静默**的：读到 20000 字符就停，不会明确告诉模型「后面还有」。
  改大文件时注意这一点。
- 白名单是**目录级**的，不是文件级——沙箱内的任何文件（除黑名单外）都可读。

## 要改它先看哪里

1. 三道边界分别对应 `files.py` 顶部的 `_DENIED_DIR_PARTS`、`_DENIED_NAMES`、`_MAX_*` 常量。
2. 路径校验逻辑在 `_resolve_within_roots()`：**改沙箱规则必须改这里**，
   不要在工具函数里另加判断。
3. `tests/unit/test_files_tools.py` 逐条覆盖了边界的每一面——加规则时同步加测试。
