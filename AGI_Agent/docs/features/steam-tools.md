# 功能：Steam 工具

- 状态：已完成（2026-10-12）。五个工具均已真实跑通，**但有一处路径未验证**，
  见下方「已知局限」第一条
- 涉及文件：`src/agi_agent/tools/builtin/steam.py`、`scripts/steam_login.py`、
  `tests/unit/test_steam_matching.py`、`tests/unit/test_steam_tools.py`
- 相关决策：[0005 用 Playwright 手写窄工具](../decisions/0005-playwright-for-browser-automation.md)、
  [0006 外部能力接入策略](../decisions/0006-external-capability-policy.md)、
  [0009 价格用公开 JSON 端点](../decisions/0009-public-json-endpoint-for-price.md)

## 要解决什么问题

让 Agent 能操作 Steam 购物车：查价格、看购物车、加购、删除。
这是**第一个会真实改动外部账号状态**的能力，因此也是审批中断与「结果不确定」
处理第一次真正起作用的地方。

**范围边界：只操作购物车，不涉及结账与支付。**

## 最终怎么做

五个工具：

| 工具 | 风险 | 作用 |
| --- | --- | --- |
| `steam.search_games` | `READ` | 搜索游戏，返回名称与 appid |
| `steam.list_cart` | `READ` | 列出购物车全部商品 |
| `steam.get_price` | `READ` | 查中国区价格 |
| `steam.add_to_cart` | `WRITE` | 加购，**幂等** |
| `steam.remove_from_cart` | `WRITE` | 删除全部同名条目，**幂等** |

`WRITE` 风险由 `policies` 依据注册表赋值，自动接入 `authorize` 的人工确认中断。

关键机制：

- **加购前先查购物车**：已在其中就直接返回「已存在」，不点按钮。这让写操作**幂等**。
- **删除前先查购物车**：本来就不在，就什么都不做，同样返回成功。
- **名称匹配一律完全同名**，不做模糊匹配。身份判定优先用 **appid**，名称只作展示。
- **删除是循环删到干净**：同名条目可能有多份（重复加购事故就会留下多份），
  每轮重新读一次购物车再删下一条，因此能扛住 React 重渲染导致的元素失效。
- **所有页面固定 `?l=english`**：界面语言随账号变化，固定后才谈得上稳定。
- **开跑前先用 8 秒超时探一次商店首页**：不通立刻报错并指明代理，
  而不是让用户等满 45 秒的默认超时（实测那句等待毫无输出，会被当成卡死）。
- **登录态在使用时自动检测**：落到了 `/login/`、或读出空购物车但本地已无登录 cookie，
  就明确要求重新扫码——**不做任何自动续期**（ADR 0006）。
  检测点在**点击之前**，所以结论是"确定没做"，可以直接停下而不必吓唬用户。
- **网络不通、登录过期一律走 `PreconditionError`**：它们重规划也修不好，只有人能修，
  所以当场停下。详见 [ADR 0011](../decisions/0011-halt-on-unmet-precondition.md)。

## 为什么这么做 / 被否决的方案

**完整论证写在代码注释里**（`steam.py` 文件头与各函数 docstring），这里只留结论：

- **为什么只接受完全同名**：三种"更省事"的匹配策略都被真实数据证伪。
  完整失败过程见 `steam.py` 的 `_pick_result()` —— **改匹配逻辑前必须先读它**。
- **为什么必须幂等**：见 [ADR 0010](../decisions/0010-no-retry-on-uncertain-write.md)
  记录的那次真实事故——一次复核失败触发了重试，购物车里留下了 3 份同一个游戏。
- **为什么删除的是"全部同名条目"**：同名重复是真实存在的（事故产物），
  删一条要反复执行才能清完。审批摘要会写明将删除 N 条。
- **被否决：挂接 Steam 桌面客户端 / 接入 Playwright MCP / 调用未公开 API** —— 见 ADR 0005。
- **被否决：拦截购物车 React 应用调用的内部接口** —— 见 ADR 0009，那才是真正被禁止的私有接口。

## 已知局限与坑

- **「一次清除多份同名条目」这条路径尚未在真实购物车上验证过。**
  已经实测的是：搜索、查价、列表、加购（含幂等拒绝重复）、删除单条（含幂等空操作）。
  要验证多份清除，得先让购物车里存在重复条目——而**加购现在已经幂等，
  Agent 自己造不出重复了**，只能人工在 Steam 里连点两次加购。
  删除循环本身有单测与边界推导，但没跑过真实数据。
- **购物车页是 React 应用，类名是构建期哈希**（形如 `_3F0SnUeC_obtI4WyQtijAA`，
  每次 Steam 发版都会变）。因此**购物车相关的能力比搜索页、商品页更脆弱**，
  可用的稳定锚点只有三个：`a[href*="/app/"]` 里的 appid、封面 `img[alt]`、
  `[role="button"]` 的文字。这是已接受的成本。
- **删除控件只能靠文字标签定位**：同一行里有 `Add` 与 `Remove` 两个 `[role="button"]`，
  结构上无从区分。匹配数不为 1 时工具**报错而不是猜**——点错控件的后果是真实的。
  若 Steam 换了界面语言，标签集合需要补。
- **购物车与推荐位都是 `/app/` 链接**：靠 `.ImpressionTrackedElement` 区分
  （推荐位是"被追踪的曝光"，购物车条目不是）。这个语义类名若消失，工具会读多，
  不会读少——多出来的条目在 `list_cart` 里肉眼可见。
- **价格固定查中国区**（`_PRICE_CC = "cn"`），换区要改这一处。
- **中英文名转换由 planner 承担**，实测把「仁王3」直接传给工具必然失败
  （商店不索引中文名），会多消耗一轮重规划。这是已知代价。
- **会话会过期**，工具会自动检测到，并明确要求重新扫码登录
  （`uv run python scripts/steam_login.py`）。这是设计如此，**不要改成自动续期**。
  检测靠两个信号：落在 `/login/`，或读出空购物车但本地已无 `steamLoginSecure` cookie。
  第二个信号只作辅助——cookie 名字若变化它会误判，所以只在结果反常时才用它。
- **搜索不需要登录**，所以会话过期时 `search_games` 仍照常工作。这是对的，不要"顺手"给它加拦截。
- **真实链路没有自动化测试**：它有真实副作用，不该被反复触发。
  单测只覆盖纯逻辑（appid 提取、价格渲染、名称匹配、注册）；浏览器部分靠人工真实运行验证。

## 要改它先看哪里

1. **改名称匹配规则** → `_pick_result()` 与 `_normalize()`，**先读那两个函数的注释**。
2. **改购物车读取** → `_JS_READ_CART` 及其上方的常量块；改完必须用真实购物车验证，
   尤其要确认推荐位没有被算进来。
3. **改删除控件定位** → `_JS_MARK_REMOVE`；它刻意做成"匹配不到就报错"。
4. **改选择器** → 文件顶部的 `_RESULT_SELECTOR`、`_CART_LINK_SELECTOR`。
5. **改复核策略** → `_poll_cart()`：**复核可以重试，动作不可以**，这条不能反过来。
6. **改失败分类** → `_network_error()`、`_login_expired()`、`_cart_unreadable()`。
   前者归 `PreconditionError`（停下），后者可能是 `ToolError`（可重试）——判据是「谁来修」。
7. **改登录检测** → `_require_login()`、`_is_logged_in()`、`_login_expired()`。
   它们**只检测，绝不续期**；扩充检测信号时不要引入任何接触凭据的代码。
8. **改登录/会话方式** → `scripts/steam_login.py`；改路径或代理 →
   `config.py` 的 `STEAM_STATE`、`BROWSER_PROXY`。
9. **安全相关**：`.secrets/` 同时受 `.gitignore` 与 `files.py` 黑名单保护，
   换存储位置时两处都要改。
