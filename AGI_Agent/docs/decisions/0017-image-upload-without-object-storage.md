# 0017 图片上传不走对象存储

- 日期：2026-10-13
- 状态：已采用

## 背景

图像理解（ADR 0012）做完之后，能力只在命令行里可用：读图工具接受的是**本机文件路径**，
而界面没有地方能把一张图喂进去。于是"多模态到底能不能用"这件事，在应用里无从验证。

用户提出可以开通阿里云 OSS 来存图片——这是一个很自然的联想（"上传"通常会想到对象存储），
所以这条决策需要被明确记录下来，而不是默默选一条路。

关键事实：**读图工具读的就是本机文件**。图片从浏览器传到这台机器上，就已经到位了；
它不需要再去任何地方转一圈。

## 决策

**不引入对象存储。** 图片走这条路径：

```
浏览器选图 → POST /api/uploads（Server 转发）→ POST /uploads（Agent 落盘）
          → 返回本机路径 → 路径写进任务目标文本 → planner 把它交给图像工具
```

四点具体安排：

1. **图片存在 Agent 侧**（`AGI_Agent/uploads/`），不存 Server 侧。
   文件是给 Agent 用的：让它写自己的沙箱，就不必再约定一个共享目录、
   也不必去改 `AGI_ALLOWED_ROOTS`。
2. **Server 只是管道**：不解析图片、不决定存哪、不记录路径。
   服务端知道得越少，将来换存储时改的地方就越少。
3. **文件名由 Agent 生成**（时间戳 + 随机后缀 + 按文件头判定的扩展名），
   不用上传方给的名字——那里面可能带路径分隔符，或者干脆是 `..\..\某个重要文件`。
4. **上传目录必须在 Agent 的沙箱内**：读图工具用 `resolve_readable_path` 校验路径，
   落在沙箱外会出现"上传成功、读图被拒"这种自相矛盾的现象，而且很难排查。
   默认放项目根下的 `uploads/`，天然满足；用 `AGI_UPLOAD_DIR` 覆盖时要留意这一点。

## 被否决的方案

- **用阿里云 OSS 存图片。** 它解决的是"多个机器之间共享文件"的问题，而我们**没有这个问题**：
  两个服务跑在同一台机器上，读图的也是本机进程。引入它要多一个外部服务、一套凭据、
  一笔费用，换来的是"传出去再取回来"。
  **它什么时候才真的必要**：`AGI_Agent` 与 `AGI_Server` 部署到**不同机器**时——
  那时两者之间没有共享文件系统。这是一个有明确触发条件的未来。
  到那时的改动也不大：换存储只落在 Agent 一处（Server 是管道，前端只认返回值里的路径）。

- **图片存在 Server 侧。** 那就得让两个服务约定一个共享目录，
  或者去改 Agent 的沙箱根把它放进来——为了一个"文件放谁家"的问题，
  在两个服务之间制造出一条隐式约定。不如把文件放在唯一的使用方那里。

- **给 `Task` 加附件字段**（而不是把路径写进目标文本）。
  这是**更正确**的做法：图片是任务的一部分，应该作为结构化字段传递，
  而不是混在自然语言里让模型去抄。没有采用是因为改动面大得多——
  要动数据契约、checkpoint 序列化、planner 提示词，还要保证旧任务兼容。
  **升级触发条件**：实测出现"模型抄错路径"（下面「后果」里那条折中），
  或者需要支持多张图 / 图片与任务解耦时。

- **让前端直连 Agent 上传。** 那会破坏 ADR 0014 定下的分层
  （前端只应该认识 Server）。多一跳换来的是：Agent 换地址、换存储方式时，前端一行都不用改。

## 后果

- **一个已知折中**：图片路径是通过**任务目标文本**传给 planner 的
  （`Task` 目前只有 `goal` 一个字段）。这意味着"图在哪"由模型从文本里抄进工具参数——
  大概率没问题，但**不是硬保证**。端到端实测通过（图里的随机数字被正确读出），
  但这只说明它在这个场景下能跑通，不构成保证。升级路径见上。

- **上传的文件不会自动清理**，会一直堆在 `uploads/` 里。
  触发条件：占用明显、或需要保留策略（比如"只留最近 N 天"）时再加清理任务。
  现在不加，是因为一个只会删文件的定时任务，在还没人抱怨之前不值得存在。

- **文件内容校验在上传这一步就做了**（文件头嗅探 + 体积上限），
  而且用的是**和读图工具同一套规则**（`agi_agent/images.py`）。
  两处各写一套的话，迟早出现"上传时接受了、调用时却拒绝"这种自相矛盾的行为。

- **服务端多了一个 4xx 的来源**：Agent 判定"这不是图片"会回 400，
  服务端原样转成 400。它与"Agent 服务不可用"（503）是两回事——这个区分必须留住，
  否则用户会去排查一个根本没坏的服务。
