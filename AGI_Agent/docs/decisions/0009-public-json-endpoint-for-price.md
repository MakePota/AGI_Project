# 0009 用公开 JSON 端点查询 Steam 价格

- 日期：2026-10-12
- 状态：已采用

## 背景

`steam.get_price` 需要一个价格数据源。两条路：解析商店页面的价格元素，
或使用 `store.steampowered.com/api/appdetails`。

后者无需登录、无需鉴权、返回 JSON，且**商店页面自己就用它渲染价格**。
但它**不在 Valve 的官方开发者文档里**——所以它落在 ADR 0006 第一条
「不使用未公开或逆向出来的 API 端点」的射程之内，必须单独裁定，
不能默认放行。

## 决策

**采用该端点查询价格。**

关键是把 ADR 0006 那条规则的**目的**说清楚：它防的是「依赖随时会失效、
且自动化访问可能违反服务条款的私有接口」，而不是「一切没有写进官方文档的 URL」。
据此把端点分成两类：

| 类型 | 例子 | 是否允许 |
| --- | --- | --- |
| **公开可访问、长期稳定、页面自身在用的数据端点** | `api/appdetails` | ✅ 允许 |
| 逆向出来的私有/内部接口 | Steam 客户端 CEF 内部 API、购物车 React 应用背后的内部 JSON 接口 | ❌ 禁止 |

判据三条，必须**同时**成立：**无需登录**、**未绕过任何权限**、**页面自身在用它**。

价格查询是只读操作，最坏情况是报错，不会改动账号状态——风险与收益不对称，值得。

## 被否决的方案

- **解析商品页的价格元素**：完全合规，但更脆弱。价格是**本地化文本**，
  格式随区域与折扣变化（实测中文界面与英文界面的按钮、名称都不同），
  而且要多开一次浏览器。同一份 JSON 里同时给了原价、现价、折扣率与货币，
  解析文本只会更差。
- **拦截购物车 React 应用调用的内部接口**：那才是 ADR 0006 真正想禁止的东西——
  需要伪造请求、随应用版本变化、失败时静默。**明确不做**，购物车一律走 DOM。
- **接第三方价格 API（如 IsThereAnyDeal）**：为查一个区的现价引入外部依赖与配额，
  不值。

## 后果

- **这是本项目采用的第一条非官方文档化的端点。** 边界必须写清楚：
  它**只用于只读的价格查询**。不得据此推论「其他内部接口也可以用」——
  每条新端点都要单独按上面三条判据审一遍，并在本目录留下记录。
- 若它失效，只有 `steam.get_price` 报错，不影响其他工具。
- 价格按**中国区**查询，硬编码在 `steam.py` 的 `_PRICE_CC`。换区改这一处。
- 附带的一个认识：购物车页已经是 React 应用，类名是构建期哈希，
  **因此购物车只能走 DOM 解析，比搜索页与商品页更脆弱**。这是已接受的成本，
  不是待解决的问题——除非将来出现真正稳定的公开接口。
