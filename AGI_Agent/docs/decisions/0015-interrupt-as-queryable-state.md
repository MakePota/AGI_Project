# 0015 「等待批准」是可查询的状态，不是挂着的连接

- 日期：2026-10-13
- 状态：已采用

## 背景

本项目的核心能力之一是**人工确认中断**：计划里只要有带副作用的步骤，图就停在 `authorize` 节点等人批准（ADR 0007）。在 CLI 里这件事很自然——`interrupt()` 把控制权交回进程，`Command(resume=…)` 续跑，全程在一个进程里（`cli.py:53-79` 的 `_drive` 就是这个循环）。

搬到 HTTP 之后，它变成一个跨请求的状态机。调研里最流行的做法是**让 SSE 连接挂着等审批**：流里吐出 `approval_requested`，生成器 `await` 一个事件对象，另一个 `POST /approve` 把事件置位，流继续。

**这条路在本项目不成立**，因为我们的链路是 **uni-app → Java Server → Python Agent 两跳**：

- 任何一跳断了、浏览器切后台了、用户刷新页面了，审批请求就丢了；
- 前端换个设备、或者用户想用 `curl` 排查，都无法「接上」那根挂着的连接；
- 两个服务之间还多一层：Java 侧挂着的连接与 Python 侧的挂着的连接要对上，任何一侧超时都会留下孤儿。

**跨语言还有一个隐蔽的坑**：Python 会在序列化时省略有默认值的字段，Java 会把它序列化成 `null`。如果两边共享的是同一套内部模型，同一个 JSON 在两侧的语义可能不同——这类差异不会报错，只会在某个边界条件下出错。

## 决策

1. **把「等待批准」暴露成一个可查询的状态**，而不是连接上的一次事件：

   ```
   GET  /tasks/{id}             → status=AWAITING_APPROVAL，并带上审批载荷
   POST /tasks/{id}/approval    → 提交 {approved, reason}，任务继续跑
   ```

   状态本来就存在 checkpointer 里，因此**断开、刷新、换客户端都不丢**。

2. **传输只是推送优化，不承载语义**。SSE 负责「不用轮询也能看到新事件」；即使把 SSE 全部关掉，只用上面那个 GET 也能完整地走完流程。这样一来传输方式是可替换的实现细节，而不是架构的一部分。

3. **跨服务契约只有三个形状**，内部模型一律不外传：

   | 形状 | 内容 |
   | --- | --- |
   | `TaskRef` | `task_id`、`status`、`created_at` |
   | `TaskEvent` | `seq`、`type`、`at`、`payload`（**对调用方不透明的 JSON**） |
   | `ApprovalRequest` | `summary`、`steps[]`（`index`/`description`/`tool`/`arguments`/`risk`） |

   `payload` 刻意保持不透明：Server 只负责转发与落库，**不需要理解内容**，因此内部 `PlanStep`/`ToolCall` 怎么改都不会波及 Java 侧。

4. **事件带单调递增的 `seq`**，并支持 `since=seq` 增量拉取。这是「重连后不丢事件、也不重复消费」的基础，也让前端可以在断线后精确补齐。

## 被否决的方案

- **让 SSE 连接挂着等审批**（`asyncio.Event` 那套，也是调研里最流行的写法）。它假设只有一个客户端、且连接不会断——上面背景里的四种情形它一个都扛不住。**这是我们与多数示例实现分道扬镳的地方。**

- **把内部的 Pydantic 模型直接导出给 Java**。省事，但把两个语言的序列化语义差异变成了接口的一部分；而且内部模型每加一个字段都要考虑 Java 侧兼容，改动成本会一路涨上去。

- **用 WebSocket 承载审批**。多一条有状态连接，还得处理重连与消息顺序；而审批的语义**本来就不依赖连接**，用连接去承载它是把简单问题做复杂。

- **不做事件 `seq`，只推流**。那样一旦断线，前端只能整段重来，或者干脆漏掉中间过程。

## 后果

- **最大的收益是抗断线**：切后台、刷新、换设备、换客户端，都能看到「有一个任务在等你批准」。这是「挂连接」方案根本做不到的。
- 前端可以先用**轮询**甚至 `curl` 验证整条链路，SSE 最后再加——实施顺序因此更稳。
- Web 层需要为每个任务维护一个**有界的事件缓冲**（带 `seq`），而不是无限增长。有界意味着旧任务的事件会被丢弃，这与「Server 不存事件」的决定一致（只存任务状态与最终结果）。
- **必须实测**：断开 SSE 后重新连上，仍能看到审批请求并能提交决定。这条不实测就等于没做。
- 与 ADR 0010/0011 的关系：那两条管的是「工具调用的结局怎么分类」，本决策管的是「人工审批怎么跨请求存活」，两者互补，互不替代。
